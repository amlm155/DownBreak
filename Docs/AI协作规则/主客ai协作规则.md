# 主客 AI 协作规则

> 目标：需要主客分工时，主吃核心、客（外置）吃辅助。
> 原则：主 AI **日常可以照常开** Cursor 子 agent；**仅当用户明确要求按本文档协作**时，才把「子 / 客」活交给外置、禁止用 `Task` 顶替。

最后核验：2026-08-11

---

## 一、角色定义

| 角色 | 是谁 |
|---|---|
| **主 AI** | 当前 Cursor 会话里的助手 |
| **客 AI** | 用户自己开的外置 AI（非 Cursor Task） |
| **用户** | 本人 |

启用本文档协作时：「子 AI / 辅助」**默认指客 AI（外置）**，不是 Cursor 的 Task/subagent。

---

## 二、何时启用 / 客活交接

1. **日常**：主 AI 可按需开 Cursor `Task` / 内置 subagent，不受本文约束。
2. **启用条件**：用户明确说要按本规则协作（例如「按主客文档」「参考主客 ai 协作规则」）。此时计划里的「子 / 客」活 = 主写出**可复制给外置**的任务说明，等用户外置完成后再验收；**不要**用 Cursor `Task` 替客跑。
3. 启用期间误把客活派成内置子代理 = 烧 Cursor token；发现后应停，改回「任务说明交给用户」。

---

## 三、分工原则（仅启用本文档时）

- **主吃核心**：加载语义、Boot 顺序、门面签名、跨层依赖、文档终稿、总验收。
- **客吃辅助**：数据批改 + gen、批量改名 UI、按已定 API 机械替换调用点、贴草稿文档。
- **主不甩锅**：不要把重活/模糊活整包甩给客；也不要把客活偷偷用 Cursor 子代理干完。
- **客不越权**：不定门面 API、不改 ModuleHub 启动序、不改 ResourceManager/Boot 加载语义（除非主任务单写明）。

---

## 四、交接格式（主 → 用户 → 客）

主 AI 交付客任务时，应给出一段**可直接粘贴**的说明，至少含：

1. 目标 / 验收标准  
2. 允许改的路径、禁止改的路径  
3. 关键文件与参考实现  
4. 完成后客应回报什么（样例对比、是否 gen 成功等）

用户把该段丢给外置客 AI；客完成后用户回主会话；主再核验并继续主线。

---

## 五、主 AI 自检清单（仅启用本文档时）

- [ ] 用户是否明确要求按主客规则协作？未要求则日常可开子 agent
- [ ] 若已启用：这项是不是「客活」？是则只写任务说明，别用 `Task` 顶替
- [ ] 「子」是否被我理解成 Cursor subagent 了？启用时应是外置客

---

## 六、案例（MmAsset）

| 编号 | 执行方 | 说明 |
|---|---|---|
| 寻址对齐 AA | 主 | 默认 alias=完整路径；短名仅 `assetAliasList`；文档终稿 |
| 拆除后缀约定 | 客（外置） | Excel/磁盘/UILoad/Animator/文档里强制 `_Sprite` 等；短名改注册别名 |
| 导出验证 | 用户 | 填充别名 → 导出地址表 → 跑一遍加载 |

反例：用户已要求主客分工时，主把客活用 Cursor Task 开跑 → **违规**。
