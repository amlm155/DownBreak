## 二、运作原理

```
Defines/*.xml（schema）
    └─ enum / bean / table（index 主键，input = sheet@xlsx）
Data/**/*.xlsx（一 sheet 一表）
    └─ 表头 4 行：##comment / ##说明 / ##var / ##type；第 5 行起数据
gen.bat
    ├─ -t client -c cs-simple-json → Gen/
    └─ -d json                     → StreamingAssets/Config/Item/
运行时
    LubanTables.EnsureLoaded()
    → new cfg.Tables(loader)
    → 按 key「模块_表名小写」读 JSON，分表强类型反序列化
```

要点：

- **JSON 名**：`{模块}_{表名小写}.json`，如 `item_tbweapon.json`、`loot_tbscrapcontainer.json`
- **组**：`c` 客户端 / `s` 服务器 / `e` 编辑器；`-t client` 只出 c 组
- **跨模块**：`loot.xml` 可引用 `item.EItemType`、`item.GridSize`
- **分表落地**：当前 `cs-simple-json` 是**一表一 JSON**，表类内直接 `DeserializeXxx`；**不是**单文件靠 `$type` 多态分派
- **值类型**：`GridSize`、`vector2/3/4` 在 Excel 填 `x,y` 逗号分隔
- StreamingAssets 随包发布，文件可替换；**尚未**接入 MmAsset 热更管线（勿写成已热更）

## 三、生成物一览（`cfg`）

### 枚举

| 枚举 | 用途 |
|---|---|
| `item.EItemType` | 0装备 1武器 2材料 3食物水分 4药品 5蓝图 6储物箱 |
| `item.EItemRarity` | 0白→5红 |
| `item.EItemStackType` | 0不可 1可堆叠 |
| `item.EEquipSlot` | 0手持 1背包 2上衣 3裤子 4头部 |
| `item.EWeaponName` | 挂点名，**与 WeaponConfig Key 对齐**（见配置管线） |
| `loot.ELootGrade` | 搜刮密度 0A→3D |

### bean / 表

- 基类 `item.Item`：id、name、description、`icon_path`、`world_prefab_path`、data_size、类型/稀有度/堆叠/耐久…
- 子类：`Equipment` / `Weapon` / `FoodOrWater` / `Medicine` / `Material` / `Blueprint` / `StorageBox`（仅 `capacity`）
- 合成：`craft.Recipe`（`item_type` 复用 `item.EItemType` 做制作页分类）
- 搜刮：`loot.ScrapContainer`、`loot.RarityGradient`
- 表类：`TbRecipe`（主键 id）、`TbEquipment`…`TbBlueprint`、`TbStorageBox`、`TbScrapContainer`（id）、`TbRarityGradient`（grade）
- 总入口：`cfg.Tables`（构造完 `ResolveRef()`）

资源类字符串字段：`icon_path` / `*_prefab_path` 一律填**短名**（须在 `assetAliasList` 注册）；`*_anim_name` 填 FP Animator **状态名**。表内不要写 `Assets/...`（见资源管线）。

## 四、运行时门面

`Assets/Scripts/0_Data/LubanTableData/Item/itemData/TableData/LubanTables.cs`

| API | 作用 |
|---|---|
| `Tables` | 懒加载 `cfg.Tables` |
| `EnsureLoaded()` / `Reload()` | 加载 / 清缓存重载 |
| `ItemList` / `ItemDict` | 七张物品表合并为 `IItemTableData` |
| `TryGetItem` / `TryGetRaw<T>` | 按 ExcelItemId 查适配器 / 原始行 |

`IItemTableData`：`GridSize`→`Vector2Int`、枚举透传；背包/UI 优先认接口。  
`ItemRtData` / `ItemRtDataMgr` 只持有 `ExcelItemId`，配置随时查表，不缓存整行 SO。

## 五、业务用法

```csharp
if (LubanTables.TryGetItem(itemTableId, out var tableData))
{
    string icon = tableData.IconPath;   // 短名 → MmAssetMgr
    string world = tableData.WorldPrefabPath; // 短名 → MmAssetMgr
    Vector2Int size = tableData.DataSize;
}

var weaponRow = LubanTables.Tables.TbWeapon.GetOrDefault(itemTableId);
var foodRow = LubanTables.Tables.TbFoodOrWater.GetOrDefault(id);
var container = LubanTables.Tables.TbScrapContainer.GetOrDefault(scrapContainerId);

```

## 六、改表流程

1. 结构：改 `DataTables/Defines/*.xml`
2. 数据：改对应 xlsx（表头 4 行与 xml 字段对齐；枚举可填数字或中文别名）
3. 生成：`DataTables/gen.bat`（或 Cursor `/luban`）
4. 回 Unity 等编译；StreamingAssets JSON 随编辑器刷新可读

注意：

- **勿手改** `Gen/`；缺 asmdef 时确认 gen.bat 已回拷
- 新表若要进统一物品缓存：改 `LubanTables.BuildItemCache`
- 新物品大类通常只需 Excel + gen；新挂点/动画还要动《配置管线》SO 与 Animator
- 表内资源字段一律短名，并在模块「地址别名」注册；完整路径只出现在 AbConfig / 代码自举，不进 Excel
